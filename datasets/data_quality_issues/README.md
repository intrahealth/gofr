# Data Quality Issue Datasets

One CSV per data-quality issue found in `datasets/combined.csv`, generated by
[`export_data_quality_issues.py`](../../tools/data_ingestion/export_data_quality_issues.py).
Regenerate any time with:

```bash
python3 tools/data_ingestion/export_data_quality_issues.py
```

See [`_index.csv`](./_index.csv) for the machine-readable manifest (issue id,
category, severity, description, record count, file) and
[`../../docs/data_quality/facility-data-quality-report.md`](../../docs/data_quality/facility-data-quality-report.md)
for the full narrative report.

## File types

- **Facility-level issues** contain the full offending records (canonical
  32-column schema) plus diagnostic column(s) — e.g. `missing_required_fields`,
  `code_issues`, `nesting_issues`, `gps_issue`, `value_issues`. Fix these rows
  and re-merge.
- **Aggregate issues** (`coverage_*`, `integrity_*_conflict`, `dupnames_*`) are
  summary tables keyed by admin code or name rather than facility records.

## Severity

| Severity | Meaning |
|---|---|
| **Blocker** | Breaks or corrupts ingestion — fix before loading (`duplicate_hf_code`, `validity_hierarchy_nesting`). |
| **Major** | Registry materially degraded (completeness, GPS, coverage, orphan codes, code↔name conflicts). |
| **Minor** | Cosmetic / normalisable (value-set typos, placeholder emails, reused names — many legitimately valid). |

> Note: `coverage_communes_no_facilities` (439) and the reused-name files are
> expectation-setting references, not necessarily defects — Cambodian commune
> names repeat legitimately, and not every commune is expected to host a facility.
